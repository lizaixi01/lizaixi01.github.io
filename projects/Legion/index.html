Legion

用 Manager 与 Worker 组织本地 Agent 任务，由独立检查器验收，保留运行证据并支持安全暂停与恢复。

查看源码 ↗下载安装包 ↗

从目标到验收

Legion 是一个本地 Agent 管理系统，驱动 Codex 执行任务。Manager 负责规划，Worker 承担分工，独立检查器决定是否通过验收。模型报告“完成”可以是交付说明，却不是验收证据。

执行过程记录 prompt、日志、产物哈希与决策，使结果可以回放复查。失败后的选项包括恢复原会话修复、换路线或停止，而不是继续累计未经检查的产物。

恢复的是同一份任务

可恢复工程入口先让用户审核需求与测试提案。批准会冻结目标、任务 DAG、源文件、测试和执行配置；交付在隔离候选目录内完成，不自动覆盖源项目。

安全暂停后可以在原任务恢复。累计调用与检查次数、原期限和既有证据继续保留，暂停不会重新获得一份预算。已经通过的节点在新进程中重新验收后，才决定是否需要再次实施。

不能把旧的 PASS 当作新的证据

恢复需要核对冻结配置、代码版本、产物、报告和检查器源码，并重新运行独立挑战与功能检查。缺失、失败或不确定的检查会阻止后续依赖推进。验证器或 Node 版本发生变化，也可能阻塞原任务恢复。

这一设计把“已经做过什么”和“当前还能确认什么”分开。恢复不是只读一份摘要，然后假设过去的所有判断依然成立。

当前边界

桌面可恢复工程入口目前只支持已有的小型、无外部依赖的 Node 行为测试项目，并发与期限均有上限。一般聊天入口的范围不同，不能把二者混为一谈。

公开恢复设计记录包含离线子进程、暂停重启、故障与集成检查的测试证据；真实模型端到端恢复、持续多日运行和任意断电尚未验证。进程权限限制也不等于完整的操作系统沙箱。本页引用这些记录，没有重新执行 Legion 测试或模型调用。
