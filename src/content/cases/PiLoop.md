## 为什么做这个项目

用户明确给出目标以后，仍可能需要反复解释偏好、告诉 Agent 去找哪些资料，或提醒它完成检查。PiLoop 的出发点是减少这些重复指导：先按需调查，明确任务继续执行，在有实质分歧时再把选择交给用户。

项目基于 Pi，沿用其运行时、终端界面、工具循环与上下文机制。PiLoop 增加的是行为约定、偏好记忆和简短配置入口；基础运行能力来自 Pi。

## 偏好应该跟着什么走

通用交流偏好和项目代码规则需要不同的作用范围。项目约束保存在项目内，一般交流偏好保存在用户配置目录。用户可用 `/memory` 查看、`/forget` 停用，也可以手动保存。

这种记忆是有预算的文本注入。它帮助减少重复指导的效果仍需要验证，不能等同于已经实现了语义检索或自主学习。

## 把检查放进交付过程

开发与修复任务的行为约定要求实际执行、检查失败并复查最终版本。网页任务可以按需调用 `verify_web_page`，执行桌面与窄屏操作和结果断言，将截图与 JSON 报告保存到项目目录。

验证工具依赖本机已有浏览器环境，CLI 的普通安装与启动不会下载浏览器。验证仍由模型选择和调用，每轮有调用上限，因此它不是禁止提前回复的硬门禁，也不保证零缺陷。

## 当前证据与边界

公开 README 对小样本实验的结论是：尚未证明 PiLoop 稳定优于原版 Pi。Dream、增强 Compaction 和后台持续工作也尚未实现。本页整理项目说明，没有重新运行 PiLoop 的模型实验。
